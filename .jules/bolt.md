## 2024-05-18 - String Manipulation in Vocab Processing
**Learning:** String replacement via `replace()` is significantly faster in Python (~4x) than iterating with a generator expression `''.join(new if cond else old for c in s)`. In vocabulary processing (`gguf-py/gguf/vocab.py`), this bottleneck is very prominent when handling BPE merges where spaces are encoded using `chr(ord(' ') + 256)`. A secondary learning is that creating a dense list to map indices is significantly faster (~5x) than a sparse mapping using `reverse_vocab = {id: encoded_tok for encoded_tok, id in self.vocab.items()}` when keys are known continuous integers.
**Action:** Replace slow `join(generator)` patterns for character replacement with `.replace()`. Also replace dictionary comprehensions with simple pre-allocated lists for dense reverse mappings when possible, e.g. for `reverse_vocab` mapping.
