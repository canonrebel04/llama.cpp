## 2024-03-24 - Optimization: Avoid np.empty().itemsize overhead in tight loops
**Learning:** In `gguf-py`, GGUF metadata reading happens in a tight loop. Checking the `itemsize` by instantiating an empty array via `np.empty([], dtype=dtype).itemsize` causes significant allocation overhead (~0.08ms per call).
Additionally, do NOT try to avoid `memmap` array slicing by replacing `data[start:end].view()` with `np.ndarray(buffer=data, offset=...)` or `np.frombuffer(data, ...)`. The GGUF specification packs key-value pairs back-to-back without alignment padding, resulting in unaligned byte offsets. Operations like `np.ndarray` and `np.frombuffer` strictly enforce memory alignment and will throw `ValueError: buffer size must be a multiple of element size` (or similar) on unaligned offsets in certain memoryview contexts, whereas the `.view()` slicing idiom safely handles unaligned data casting in numpy.
**Action:** Always fetch `itemsize` statically using `int(np.dtype(dtype).itemsize)` to avoid the array allocation overhead, while safely retaining the `.view()` slicing approach for unaligned binary data.
