## 2026-08-16 - [numpy.memmap performance overhead]
**Learning:** numpy.memmap imposes significant overhead compared to numpy.ndarray when indexing repeatedly. Specifically, we noticed that using `self.data[offset:end_offs]` on a `memmap` array calls `__array_finalize__` and `__getitem__` repeatedly, adding ~1.2s overhead per 10k tensors during `GGUFReader` initialization. Converting `memmap` directly to `ndarray` via `.view(type=np.ndarray)` on load eliminates this overhead and speeds up reading by ~3x.
**Action:** When implementing `GGUFReader` which reads lots of metadata directly from an underlying memory-mapped file structure, use `.view(type=np.ndarray)` on the loaded `memmap` to bypass the costly overhead of `.memmap.__getitem__` on small metadata reads while preserving the zero-copy behavior of the underlying buffer.
